# Universal Ambient Light

Android向けのアンビエント画面照明。アプリが画面をキャプチャする（またはデバイスのカメラで
テレビを撮影する）ことで、端の色を抽出し、LEDストリップ、コントローラー、またはスマート
ライトへストリーミングします。キャプチャなしでもライトエフェクトを実行できます。
Android 8.0以降で動作し、スマートフォンとAndroid TVの両方に対応しています。

## 機能

- **17種類の出力**: WLED、DDP、E1.31 (sACN)、Art-Net、tpm2.net、UDP raw、Open Pixel
  Control、Adalightおよびその他のUSBボード、Philips Hue、Nanoleaf、WiZ、Yeelight、LIFX、Govee、
  Zigbee2MQTT、Home Assistant、およびHyperion / HyperHDRサーバー。
- **デバイス検索**: ローカルネットワーク上のWLED、Hyperion、HyperHDR、Hueブリッジ、Nanoleaf、
  Home Assistant、WiZ、Yeelight、LIFX、Govee、Art-Netノードを数秒で検出します。
- **複数コントローラー同時利用**: メインコントローラーに加えて、例えば壁の2台目のWLEDや
  テレビ側面のバーなどを追加できます。それぞれに独自のアドレス、LEDレイアウト、画面の
  担当領域があります。
- **スマートフォンとAndroid TV**: タッチスクリーン用とD-pad操作向けに別々のレイアウト。
- **カメラキャプチャ**: デバイスのカメラでテレビを撮影し、四隅で遠近補正を行います。
  画面キャプチャが使えないテレビ向けです。
- **キャプチャなしのライトエフェクト**: 単色、グラデーション、ムービーホワイト、虹、炎、
  キャンドル、オーロラなど。
- **カラーミュージック**: 周波数に応じてストリップを点灯するエフェクト。低音は下、高音は上。
  マイクまたはデバイス自身が再生する音声から取得します。
- **アプリごとの照明遅延**と自動調整: スマートフォンのカメラがテレビと光を撮影し、
  再生中の映像に対してストリップがどれだけ先行しているかを測定します。
- **調整可能なパイプライン**: キャプチャ品質、フレームレート、色のスムージング、レイテンシ。
- **自動起動**: 起動後、テレビのスリープ後、アプリ更新後。**自動再接続**: 接続切断後。
- **フォンリモコン**: QRコードでテレビとペアリングし、スマートフォンからテレビの照明の
  開始・停止・すべての設定変更が可能。タッチパッドマウスとキーボード付きのテレビリモコン
  としても使えます。
- **設定のバックアップ**: すべての設定をファイルへ書き出し・読み込み。テレビではフォン
  リモコン経由でも可能。
- **スリープタイマー**: 15分から2時間後に照明をオフにします。
- **平均色モード**: フルストリップの代わりに1色の支配色を送信。低性能デバイス向け。
- **クイック設定タイル**: ライトのオン/オフ切り替え用。

## 対応コントローラー

|---|---|---|
| ネットワーク経由のストリップ | WLED | DDPまたはUDP raw、色順、RGBW、輝度制限 |
| | DDP | WLED、ESPixelStick、FPPおよびその他のDDPレシーバー |
| | E1.31 (sACN) | 開始ユニバース、ユニバースあたりのLED数、ユニキャストまたはマルチキャスト |
| | Art-Net | ArtDmx、開始ユニバース、ユニバースあたりのLED数 |

| | Open Pixel Control | TCP経由のFadeCandy / fcserver |
| USB経由のストリップ | AdalightおよびUSBキット | Ada、LightBerry APA102、AWA (HyperSerial)、tpm2、Skydimo、SEDU、KarateLight、AtmoLight、SP616E |
| スマートライト | Philips Hue | ブリッジ経由、ボタンでペアリング。エンターテイメントエリアは最大毎秒25回のストリーム |

| | WiZ、Yeelight、LIFX、Govee | ローカルネットワークプロトコル、クラウド不要 |

ライトとパネルは画面ゾーン（左、上、角、画面全体など）の色を受け取り、ストリップの
フレームレートではなく、デバイスが処理できる速度で映像に追従します。

## 動作要件

- Android 8.0 (API 26)以上。
- 画面キャプチャ権限（MediaProjection）。
- ローカルネットワークアクセス（ネットワークコントローラーおよびライト用）、またはUSB Host
  サポート（Adalightおよびその他のUSBボード用）。

## 設定

### 1. 接続
1. アプリを起動し、**Settings**を開くか、ホーム画面の**Set up the controller**を押します。
2. コントローラー画面にはネットワーク上で見つかったものが一覧表示されます。デバイスを選ぶか、
   下のリストで種類を選び、アドレスを手入力します。**Check every address**は、mDNSで自己
   告知しないWLEDとHyperionをサブネット全体からスキャンします。1〜2分かかります。
3. HueブリッジとNanoleafパネルは、デバイス上のボタンでペアリングします。ライト（Hue、WiZ、
   Yeelight、LIFX、Govee、Zigbee2MQTT、Home Assistant）はその後、画面ゾーンに割り当てます。
   ライト横の**Blink**でどれかを確認できます。エンターテイメントエリアのあるHueブリッジは
   エリア経由でも動作でき、その場合ゾーンは不要です。
4. 検索から選んだWLEDでは、アプリがWLED側のLED数を読み取り、アプリのLEDレイアウトの数が
   異なる場合に通知します。

### 2. LED設定
- **Per-Side LED Configuration**: 各辺を個別に設定できます:
    - Top: 60 LEDs（デフォルト）
    - Right: 34 LEDs（デフォルト）
    - Bottom: 60 LEDs（デフォルト）
    - Left: 34 LEDs（デフォルト）
- **LED Layout**: 開始コーナー、方向（時計回り/反時計回り）、各辺の有効/無効を設定します。

### 2.1. 追加コントローラー
**Settings → Additional controllers**では、メインコントローラーと同時に動作し、同じ映像を
表示する出力を追加できます。ここでのコントローラー設定はメインと同じです。デバイスや種類を
選び、アドレスを入力し、LEDレイアウトを開きます。

- **壁のフレーム**は、独自のLED数を持つ同じ周囲レイアウトです。
- **テレビ側面のバー**は片側だけのレイアウトです。左側の数を設定し、他は0のままにします。
  **Scan depth**は、映像のどれだけ奥まで見るかを決めます。
- **辺の一部**はキャプチャマージンで設定します。上辺ストリップで右マージン75%にすると、
  上辺の左1/4が残ります。
- **混在出力**も可能です。メインをAdalight、横にWLEDバー、またはストリップと
  Home Assistantランプなど。Adalight自体はメインコントローラーのみになれます（USBを開く
  ため）。

スムージングと出力遅延は全コントローラー共通なので、ストリップは揃って動きます。映像設定も
共通です。WLEDとDDPの輝度はコントローラーごとに設定します。コントローラーのレイアウト内の
**Show LED layout test**は、そのコントローラーだけを点灯します。接続できないコントローラーが
他を止めません。バックグラウンドで再試行し、ログにだけ表示されます。

### 3. キャプチャ設定
- **Capture Source**: **Screen**（デフォルト）または**Camera**モードを選択。
    - *Screen*: MediaProjection APIによる標準の画面キャプチャ（画面キャプチャ権限が必要）。
    - *Camera*: デバイスカメラと遠近補正を使う代替方式。画面キャプチャ非対応のテレビや、
      外部スマートフォン構成に最適。
- **Capture Rate (FPS)**: デフォルト30 FPS（選択肢: 10、15、24、30、60）。
- **Capture Quality**:
    - *Low (64px)* — 低性能デバイス向け、またはレイテンシ削減用。
    - *Medium (128px)* — バランス型（デフォルト、推奨）。
    - *High (256px)* — 高性能デバイスのみ。
    - *Ultra (512px)* — ハイエンド向けの最高品質。
- **Send Average Color**: 最大パフォーマンス用に有効化（ストリップ全体に単色を送信）。
- **Black bar detection**: デフォルトはオフ。上下または左右に黒帯がある映画向けにオンにします。
  端は画面境界ではなく映像から取得されます。**Black threshold**の18はほとんどのソースに
  適しています。帯が見つからない場合は24〜30に上げてください。
- **Ignore subtitles in the bottom bar**: 黒帯検出のオプションで、デフォルトはオフ。帯の高さは
  上端から求め、下端は角付近のみ確認し、暗いシーンでもクロップを維持します。映像上の字幕は
  引き続きLEDに届きます。

### 3.1. カメラモードのセットアップ
キャプチャソースに**Camera**を使う場合:
1. 求められたら**Camera**権限を許可します。
2. **Settings** → **Camera Corner Setup**を開きます。
3. カメラがテレビ画面を見える位置にデバイスを置きます。
4. 四隅のマーカー（TL、TR、BR、BL）をテレビ画面の端に合わせてドラッグします。
5. **Save**をタップしてコーナー位置を保存します。
6. アプリはキャプチャ中、これらのコーナーで遠近補正を行います。

**ヒント:**
- キャプチャ開始前に、メイン画面のライブプレビューでデバイス位置を調整してください。
- カメラがテレビ画面をはっきり見えるよう、十分な照明を確保してください。
- コーナー調整により、テレビに対してカメラが直角でない配置も補正できます。

Camera Corner Setupの**Find the TV**は、コーナーを自動配置しようとします。4秒間フレームを
監視し、明るさで点灯パネルと部屋を区別し、映像の変化の有無でテレビとランプや窓を区別した
うえで、結果をオーバーレイに読み込みます — Saveを押すまで保存されません。測定中はストリップを
暗く保ちます。そうしないと壁への自発光が画面の一部として読み取られるためです。

完成した設定というより出発点として扱ってください。点灯した映像の輪郭を取り、パネル自体では
なく、明るい部屋では混乱しやすく、その後コーナーを手で微調整することがほとんどです。何も
見つからない場合は理由を表示し、保存済みコーナーはそのままです。詳細な理由はlogcatの
`AutoFrameDetection`および`CameraEncoder`に出力されます。

### 3.2. カメラスリープモード
カメラキャプチャはテレビからのスタンバイ信号を受け取らないため、電源オフの画面でもセンサー
ノイズがストリップへ流れ続けます。**Camera Sleep Mode**設定グループ（キャプチャソースが
**Camera**のときのみ表示）は、校正済み画面領域を監視し、表示すべき新しいものがなくなると
キャプチャパイプラインを一時停止します。デフォルトは無効です。

- **Enable sleep mode**: 機能のマスタースイッチ。
- **Sleep delay (seconds)**: ストリップをオフにする前に、映像が空白のままである必要がある時間。
  範囲: 5〜3600秒、デフォルト120。反応を速くするなら下げ、暗いシーンでスリープが発動するなら
  上げてください。
- **Blank screen threshold (0–96)**: 監視領域の平均輝度がこれ以下なら画面を空白とみなします。
  デフォルト: 12。電源オフのテレビが検出されない場合は上げてください。
- **Motion sensitivity threshold (1–64)**: 動きとみなすために必要な最小の映像変化。
  デフォルト: 4。センサーノイズでストリップが何度も起きる場合は上げてください。
- **Sleep on a static picture**: 映像の変化が止まったとき（一時停止した動画、静止メニュー）も
  フレーム送信を一時停止し、ストリップは最後の色を保持します。デフォルトは無効。長い静止
  シーンではストリップの色が固まるためです。

スリープモード中、カメラはバインドされたままですが、フルの遠近補正パイプラインではなく、
疎な輝度グリッド上で5 Hzでサンプリングされます。起床には閾値を超える連続2サンプルが必要なので、
単一のノイズフレームでストリップが点滅することはありません。4つの設定はすべてキャプチャ実行中に
調整できます。ライブフィードに対してのみ校正できるためです。

### 3.3. 色と輝度
**Color processing**はデフォルトでオフで、ストリップは画面の色をそのまま受け取ります。
AdalightスケッチとほとんどのUSBボードはガンマ補正なしでLEDへ渡すため、中間調は画面より
ストリップ上で明るく見え、色は薄くなり、動画の黒帯（そこでの黒はしばしば255中の16）が
わずかに光ります。そのようなストリップでは、次から始めてください:

- **Color processing**: オン。
- **Gamma R**、**Gamma G**、**Gamma B**: 45%。スケールは反転しています。100%未満では中間調が
  暗くなり、色が濃くなり、暗いグレーが消えます。45%はガンマ2.2に相当します。
- **Saturation**: 120〜140%。
- **Brightness**: ここで下げるか、スケッチの`BRIGHTNESS`定数で下げます。

スライダー下のプレビューは、純色のR、G、Bとグレーランプでの結果を示します。Hyperionは
自身の側でガンマ補正するため、通常は色処理はそのままにします。

### 4. スムージング
- **Enable Smoothing**: デフォルトはオフ。オフだとストリップが毎フレームを繰り返し、シーン
  変化でちらついて見えます。映画ではオンにしてください。
- **Preset**: デフォルトは「Off」。プリセットを選ぶとスムージングが自動でオン/オフされます。
  「Responsive」: 50 ms遷移、60 Hz。「Balanced」: 200 ms、出力遅延80 ms、25 Hz。「Smooth」:
  500 ms、200 ms、20 Hz。
- **Settling Time**: デフォルト50 ms、0〜1000 ms。
- **Output Delay**: デフォルト0 ms、0〜1000 ms。ストリップが映像より先行する場合に上げます
  （**Lighting delay**、セクション7はアプリごとに行います）。
- **Update Frequency**: デフォルト60 Hz（20、25、30、40、50、60 Hz）。

### 5. 起動
1. 求められたら**Screen Capture / Casting**権限を許可します。
2. ボタンを切り替えてグラバーを開始します。

### 6. エフェクト
ホーム画面のパレットボタンでエフェクトを開きます。エフェクトは画面キャプチャなしでストリップを
点灯します。権限ダイアログはなく、テレビに何が表示されていても関係ありません。静的: 単色、
グラデーション、ムービーホワイト（色温度、6500 Kが基準白）。アニメーション: 虹、カラーサイクル、
ブリージング、キャンドル、炎、オーロラ、オーシャン、プラズマ、コメット。**Layout test**は
各辺を異なる色で塗り、最初のLEDから白い点が走って、誤ったLEDレイアウトをはっきりさせます。

**Color music**は、アプリが動作しているデバイスのマイク、またはデバイス自身が再生する音声
（Sound source: Sound of this device、マイク不要）から音を取ります。後者は、DolbyまたはDTS
ビットストリーム（パススルー）としてレシーバーへ送られる音は見えません。Androidをバイパスする
ためです。音は16の周波数帯に分割されます。低音は画面下部を赤で点灯し、帯は側面を上がり、
上辺中央で青に達します。ストリップは、直近1.5秒の平均を超えて音が上がったときに反応します。
ビートや変化はフラッシュし、部屋のノイズのような定常音は数秒でフェードします。Sensitivityは、
どれだけの上昇でストリップを点灯するかを決めます。音はデバイス上で分析され、録音されません。
両方のソースにオーディオ録音権限が必要です。フォンリモコンではこのエフェクトは提供されません。
権限をテレビ側で許可する必要があるためです。

**Keep on when the TV screen is off**は、TVボックスが起動したままの間、ナイトライトとして
エフェクトを続けます。一部のテレビはスタンバイでネットワークを切るため、その場合はストリップも
暗くなります。

### 7. 照明遅延
プレイヤーとソースは映像処理が異なるため、ストリップが映像より先行する量はアプリごとに
異なります。Settings → **Lighting delay**には全アプリ共通の遅延と、独自の値を持つアプリの
リストがあります。テレビは、そのアプリが画面にある間、その値に切り替えます。アプリごと設定には
使用状況へのアクセスが必要で、自動起動権限と一緒にADB経由で付与します。

**Tune with the camera**は、テレビとペアリングしたスマートフォンから実行します。スマホが
約1分間、テレビと壁の光を撮影し、両方のシーン変化を検出してずれを求めます。開始時に数秒間
ストリップが暗くなり、スマホがフレーム内の画面を探します。暗い部屋、動きのあるシーン、
画面全体と周囲の壁がフレームに入ることが必要です。結果には精度の見積もりが付き、再生中の
アプリまたは全アプリ向けに保存されます。映像より遅れているストリップは遅延では直せません。
スムージングを下げるか、より速いキャプチャ方式を選んでください。

### 8. 設定のバックアップ
**Settings → Save settings to a file**は`Download/universal-ambient-light-<date>-<time>.json`に
書き出します。Android 8および9では、代わりにシステムのファイルピッカーが開きます。
**Restore settings from a file**は、現在のすべての設定をファイルの内容で置き換えます。

- ファイルには追加コントローラーを含むすべての設定と、ライトのトークンおよびパスワードが
  平文で含まれます。
- スマートフォンとのペアリング、ADBキー、システム権限はファイルに含まれません。再インストール後に
  再設定します。
- このビルドまたはデバイスにないキャプチャ方式はスキップされ、現在のものが残ります。
- Android TVにシステムファイルピッカーがない場合、復元にはファイルマネージャーが必要です。
  ない場合はスマートフォンとペアリングし、その設定内の同じ2項目を使います。ファイルはスマホに
  残り、設定はテレビへ送られます。

### コントローラー別の詳細

#### Hyperion
- **Host/Port**: サーバーIPとポート（デフォルト`19400`）。
- **Priority**: `100`（デフォルト）。
- [Hyperion Documentation](https://docs.hyperion-project.org/)

#### WLED
- **Host**: コントローラーIP。
- **Port**: `4048`（DDP）、`19446`（UDP Raw、WLEDのHyperion入力）、または`21324`（UDP Raw、WLED独自のリアルタイムポート）。
- **Protocol**: DDP（推奨）。
- **Color Order**: WLED設定と一致させてください（例: WS2812BならGRB）。
- **RGBW**: 任意のストリップ長でDDP経由、およびポート`21324`のUDP Raw経由（DRGBW、最大367 LED）で動作します。ポート`19446`はWLEDのHyperion入力で、生RGBのみ、白チャンネルなし、最大490 LEDです。
  アプリ自身が白チャンネルを抽出します（R、G、Bに共通の成分をWへ移す）。そのためWLEDではストリップタイプをRGBWにし、**Calculate white channel from RGB**を`Manual only`または`Dual`にする必要があります。自動モードでは、WLEDは受け取った白の値を捨て、すでに減ったRGBから再計算し、結果はゼロになります。白LEDは暗いまま、色は薄く見えます。
- [WLED Documentation](https://kno.wled.ge/)

#### E1.31 と Art-Net
- **Start universe**: ストリップの最初のユニバース。**LEDs per universe**より長いストリップは
  次のユニバースへ続きます。
- **LEDs per universe**: 170ですべての510チャンネルを埋めます。レシーバーの値が異なる場合は
  そちらに合わせてください。
- アドレスが空のE1.31は、`239.255.x.y`へのマルチキャストとして送信されます。

#### tpm2.net, UDP raw, Open Pixel Control
- tpm2.netはフレームを番号付きパケットに分割し、サイズはパケットあたりのLED数で設定します。
- UDP rawにはヘッダーがまったくないため、ストリップ全体が1データグラム（490 LED）に収まる
  必要があります。
- OPCはポート`7890`へのTCP接続を維持します。チャンネル0はサーバーの全チャンネルをアドレスします。

#### Philips Hue
- デバイス検索でブリッジを選ぶかアドレスを入力し、ブリッジの丸いボタンを押し、30秒以内に
  **Pair**を押します。
- Hueアプリにエンターテイメントエリアがある場合、アプリがその使用を提案します。ブリッジは
  その後、ポート`2100`で最大毎秒25回のDTLSストリームを受け取り、エリア内の各ライトがHueアプリで
  設定した位置の色を取ります。左から右、および床、テレビ高さ、天井。Hue API v2経由では、
  グラデーションライトストリップが独自の位置を持つ複数チャンネルに分割され、長さ方向に
  複数色を表示します。API v2のないブリッジとdiyHueは古いストリームを受け取り、そのような
  ストリップは1色の1ライトになります。エリアは最大10ライトまで。ストリーム中は、ブリッジの
  他のシーンやオートメーションはこれらのライトに触れません。
- アプリのバージョン1.xでペアリングしたブリッジにはストリーミングキーがなく、エリアを使うには
  再度ペアリングが必要です。
- エリアがない場合、ブリッジのライトは**Lights and zones**に一覧され、それぞれに画面ゾーンが
  割り当てられます。色は各ライトの色域に変換されます。ブリッジは全ライト合計で毎秒約10コマンドを
  受け取るため、更新レートはそれらで共有されます。

#### Nanoleaf
- コントローラーの電源ボタンを5〜7秒押し続け、ライトが点滅したら、30秒以内に**Pair**を
  押します。
- 各パネルは、他との相対位置に応じた壁上の場所の色を取ります。

#### WiZ, Yeelight, LIFX, Govee
- ライトはローカルネットワーク上で見つかり、クラウドもアカウントも不要です。
- YeelightではYeelightアプリで**LAN Control**を有効にする必要があります。アプリは各Yeelightを
  ミュージックモードに切り替え、毎分60コマンドの制限を解除します。
- GoveeではGovee Homeアプリでデバイスの**LAN Control**を有効にする必要があります。LAN APIは
  デバイスあたり1色を設定し、ストリップのセグメントは個別にアドレスできません。

#### Zigbee2MQTT
- アドレスとポート（デフォルト`1883`）は、Zigbee2MQTTが使うMQTTブローカーのもので、
  例えばHome AssistantのMosquittoアドオンです。ログイン、パスワード、ベーストピック
  （デフォルト`zigbee2mqtt`）は接続設定で指定します。
- ライト一覧は保持された`zigbee2mqtt/bridge/devices`メッセージから来て、ライトを公開する
  デバイスのみが表示されます。色は`zigbee2mqtt/<name>/set`に発行されます。
- Zigbeeは速いシーンには遅く、ライトあたり毎秒数回の更新が、遅延なくネットワークが
  受け取れる程度です。

#### Adalight (USB)
- **Baud Rate**: `115200`（デフォルト）、またはファームウェアに合わせてください。HyperSerial
  ファームウェアは通常`2000000`で動作します。
- **Protocol**: ADA（標準Arduino）、LBAPA（APA102）、AWA（HyperSerial）、tpm2、Skydimo、
  SEDU、KarateLight（8または16チャンネル）、AtmoLight（5チャンネル）、SP616E。
- [Adalight Repository](https://github.com/adafruit/Adalight)

##### Adalight用Arduinoスケッチ

アプリ互換のすぐ使えるArduinoスケッチが[`adalight-sketch.ino`](adalight-sketch/adalight-sketch.ino)にあります。

**クイックスタート:**

1. **FastLEDライブラリをインストール:**
    - Arduino IDEで: `Tools` → `Manage Libraries` → 「FastLED」を検索 → インストール

2. **スケッチを設定:**
    - `adalight-sketch/adalight-sketch.ino`を開く
    - ファイル先頭の定数を変更:
        - `DATA_PIN` — LEDストリップ接続ピン（Uno/Nanoではデフォルト9、ESP32およびESP8266では2）
        - `NUM_LEDS` — ストリップのLED数（アプリ設定と一致させる必要があります！）
        - `LED_TYPE` — LEDストリップの種類（WS2812B、WS2811、SK6812など）
        - `COLOR_ORDER` — 色順（WS2812BはGRB、他はRGB）
        - `BRIGHTNESS` — 輝度（0-255）

3. **配線:**
    - LEDストリップ DATA → Arduinoピン（デフォルト9）
    - LEDストリップ VCC → Arduino 5V（長いストリップでは外部電源）
    - LEDストリップ GND → Arduino GND
    - **重要:** 長いストリップ（>10 LED）では、外部5V電源を使ってください！

4. **スケッチをアップロード:**
    - USBでArduinoをコンピュータに接続
    - Arduino IDEでボードとポートを選択
    - スケッチをアップロード

5. **Androidに接続:**
    - Arduinoをコンピュータから外す
    - USB OTGケーブルでArduinoをAndroidデバイスに接続
    - アプリで接続タイプを選択: **Adalight**
    - Baud Rateを設定: **115200**
    - プロトコルを選択: **ADA**
    - アプリのLED数がスケッチの`NUM_LEDS`と一致していることを確認

**WS2812B配線例:**
```
WS2812B DATA → Pin 9 Arduino
WS2812B VCC  → 5V Arduino (or external 5V)
WS2812B GND  → GND Arduino
```

**他のLEDタイプ向け:**
- **APA102 (SPI)**: FastLEDライブラリで`APA102`構成を使い、アプリでは**LBAPA**プロトコル
- **WS2811**: WS2812Bと同様、通常は`COLOR_ORDER = RGB`
- **SK6812**: WS2812Bと同様、通常は`COLOR_ORDER = GRB`

**トラブルシューティング:**
- LEDが点灯しない場合: 配線を確認し、スケッチとアプリで`NUM_LEDS`が一致していることを確認
- 色が違う場合: `COLOR_ORDER`を変更（RGB、GRB、BRGを試す）
- データが届かない場合: Baud Rate（115200であるべき）を確認し、USB OTGケーブルがデータ転送に対応していることを確認

## Android TVの機能
このアプリケーションはAndroid TV向けに完全最適化されており、Leanback LauncherとD-pad操作に
対応しています。テキスト入力（IPアドレス）を簡単にするには、スマートフォンの「Google TV」または
「Android TV Remote」アプリの使用を推奨します。

## フォンリモコン
同じアプリを実行しているスマートフォンから、テレビの照明を制御できます。オン/オフと、他の
アプリで映画再生中を含むあらゆる設定変更が可能です。色、輝度、LEDレイアウトは即座に適用され、
コントローラーアドレス、プロトコル、スムージングはキャプチャを再起動せずに約1秒以内に適用されます。

1. テレビ側: ホーム画面 → **Control from a phone**（またはSettings → Remote control）。画面に
   QRコード、アドレス、ペアリングコードが表示されます。
2. スマートフォン側: ホーム画面 → **TV remote** → **Scan QR code**。カメラで読めない場合は、
   アドレスとコードを手入力します。
3. スマートフォンはテレビを記憶し、次回起動時に再接続します。ホーム画面の**Disconnect**で
   スマートフォンは自身の照明に戻ります。

スマートフォンとテレビは同じローカルネットワーク上にある必要があります。接続はQRコードのキーを
使ったAES-256-GCMで暗号化されます。テレビの**Change the pairing code**はすべてのスマートフォンを
切断します。アクセスがオンの間、テレビは通知付きのバックグラウンドサービスを維持します。それがないと、
テレビ側アプリが閉じているときにスマートフォンから照明をオンにできません。

スマートフォンは、テレビ自体のADB設定にも便利です。Wireless debuggingの6桁コードをスマホで入力し、
テレビがペアリングポートを自分で見つけます。

カメラコーナーはテレビ自体でドラッグします。スマートフォンからは自動画面検索のみ利用できます。

スマートフォンのホーム画面の**Remote**は、それをテレビリモコンにします。D-pad、Back、Home、音量と
再生ボタン、テレビ上のカーソルを動かすタッチパッド（タップでクリック、2本指でスクロール）、
入力がすぐにテレビに表示されるテキストフィールド、起動用のテレビアプリ一覧。ボタン、マウス、
テキストはテレビ上のADB経由です。ADBなしではシステムボタン、タップ、アクセシビリティサービス経由の
テキストのみ利用できます（GitHubおよびRuStoreビルド）。

## 自動起動
**Grab on Boot**（デフォルトでオン）は、照明が以前オンだった場合、テレビの起動後、スリープからの
復帰後、またはアプリ更新後に照明を戻します。スリープ後はシステムアラームのウォッチドッグが再起動する
ため、テレビがスリープ中にアプリをアンロードするファームウェアでも戻ります。

MediaProjectionを使わないキャプチャ方式（Scrcpy/ADB、Screencap、Accessibility、Camera）には
他に何も不要です。Android 10+のMediaProjectionは画面上の確認が必要で、アプリがADB経由でしか
付与できない権限を持っていないと、Androidはバックグラウンドからそれを表示しません。ADBを
ペアリングしたら、Settings → **Autostart permissions** → **Grant via ADB**を開きます。以降、
照明はダイアログなしで開始します。

ファームウェアがテレビのスリープ中にアプリを強制停止する場合、次の起動まで何も戻せません。これは
ファームウェアの制限です。

## 外部制御（KeyMapper、Tasker、リモコンボタン）
アプリは、アクティビティを起動できる任意の自動化ツールが使える透明なトグルアクティビティを公開して
います — 例えば[KeyMapper](https://github.com/keymapperorg/KeyMapper)でリモコンボタンに割り当て:

- Component: `com.vasmarfas.UniversalAmbientLight/com.vasmarfas.UniversalAmbientLight.common.ToggleActivity`
- アクションなしではトグル: 動作中なら停止、そうでなければ開始。
- アクション`com.vasmarfas.UniversalAmbientLight.action.TURN_ON`では開始のみ、`com.vasmarfas.UniversalAmbientLight.action.TURN_OFF`では停止のみ。

adbからテスト:

```
adb shell am start -n com.vasmarfas.UniversalAmbientLight/com.vasmarfas.UniversalAmbientLight.common.ToggleActivity
adb shell am start -a com.vasmarfas.UniversalAmbientLight.action.TURN_OFF
```

開始時は、MediaProjectionが不要なキャプチャ方式（Accessibility、Scrcpy/ADB、Screencap、Camera）が
選ばれていない限り、システムの画面キャプチャダイアログが表示されます。

## 重要な注意事項

### TCLテレビ利用者
TCLデバイスでは、アグレッシブなシステム電池最適化がバックグラウンドサービスを終了させることが
あります。
**解決策:**
1. **Settings > Apps > Special App Access > Auto-Start**へ移動。
2. Universal Ambient LightのAuto-Startを有効化。
3. あるいは「Safety Guard」アプリを確認し、アプリを例外に追加。

### Fire TV
Fire TV Stickで開始ボタンが何もしない場合、オーバーレイと画面キャプチャ権限をadb経由で付与して
ください。Stickで**Developer options > ADB debugging**を有効にし、コンピュータから
`adb connect <stick-ip>:5555`で接続して実行:

```
adb shell appops set com.vasmarfas.UniversalAmbientLight SYSTEM_ALERT_WINDOW allow
adb shell appops set com.vasmarfas.UniversalAmbientLight PROJECT_MEDIA allow
adb shell am force-stop com.vasmarfas.UniversalAmbientLight
```

Fire TV Stick HD、Fire OS 7.7.1.6でテスト済み。Accessibilityキャプチャ方式はAndroid 11が必要で、
Fire OS 7（Android 9）では動作しません。

### 高品質動画再生（4K/HDR）
高品質映像（2K/4K/HDR）の再生中にアンビエントライトが有効だと問題が出るのは、多くのテレビの
ハードウェア制限です。内蔵プロセッサは、重い映像デコードと画面キャプチャの同時処理にしばしば
耐えられません。これはソフトウェアではほとんど直せない深い問題です。

**映像のスタッターやラグがある場合:**
1. 映像再生品質を1080pまたは720pに下げてください（テレビの性能に依存）。
2. または高解像度コンテンツ視聴中はアンビエントライトアプリを完全に無効にしてください。
3. キャプチャ品質とFPS設定を調整できますが、問題を完全に解決できる可能性は低いです。

**映像があるべき場所が黒いプレビューになる場合（4K/HDR、HEVC/VP9 — または一部のテレビでは*すべての*映像）:**
Hyperion/WLED/HyperHDRプレビューで、メニュー、サムネイル、写真、アプリ内テスト色は正しく
キャプチャされるのに、映像があるべき場所が黒い矩形になる場合、これは**DRMの問題ではありません**。
Androidでは映像は専用の**ハードウェアビデオプレーン（オーバーレイ）**に描画され、ディスプレイ
ハードウェアが合成してSurfaceFlingerをバイパスします。`MediaProjection`はSurfaceFlingerが
合成したものだけを見るため、映像領域は真っ黒になります。通常は4K / HEVC 10-bit / HDR10 /
Dolby Visionのみが影響し、通常の1080pは通常のスタックを通ります — **しかし一部のデバイスは
_すべての_映像をオーバーレイ経由にします**（例: いくつかのSonyモデル）。**他では解像度ではなく
コーデックに依存します**: Amlogicボックスでは、HEVC/VP9/AV1再生はどの解像度でも黒くなり、
H.264 (AVC)は完璧にキャプチャされます。それらのデコーダがAFBC圧縮フレームを直接ビデオプレーンへ
渡すためです。黒い*ローカル*ファイルはDRMを除外します。これは、他のすべてのAndroidアンビエント
ライトツール（Hyperion Android、Lightpackアプリなど）にも影響するプラットフォーム制限です —
標準の`MediaProjection`パスに修正はなく、`Scrcpy` / `Screencap` / `ADB`方式もSurfaceFlingerの
背後にあるため、同じ黒い領域を示します。

回避策:
1. **H.264 (AVC)を強制** — HEVC/VP9/AV1だけが黒くなる場合: SmartTubeではVP9の代わりにAVCストリームを選択。JellyfinではクライアントのHEVC/AV1ダイレクトプレイを無効にする（またはビットレートを制限）し、サーバーがH.264へトランスコードするようにする。
2. **再生を1080pに下げる** — プレイヤー/サーバーで（Jellyfin → デバイスごとに最大ビットレート/解像度を設定。Kodi → 再生設定を調整。mpv → `--hwdec=no`と`--vo=gpu`）。1080pはほぼ常に通常の合成スタックを通ります。
3. **プレイヤーでハードウェアデコードを無効化**（Jellyfin Android: Settings → Player → 「Prefer FMP4」と「Allow background audio playback」をオフ。mpv → `--hwdec=no`）。ソフトウェアデコードはフレームを合成パスへ強制し、キャプチャを復元します。
4. **ルート済みデバイス向け** — Settingsで`Screencap (Root)`または`Screencap (Shell)`キャプチャ方式を試す — これらは`MediaProjection`ではなく`screencap`バイナリ経由で、一部のキャプチャ制限に役立ちます。`screencap`もSurfaceFlingerの出力を読むため、ハードウェアビデオプレーンは**復元しません**。
5. **MediaTek SoCテレビでは**、実験的な`MTK THAL Capture`方式がベンダーDIPエンジンから直接キャプチャし（合成前）、そこで4K HDRが動作します — ただしルートとMTKチップの両方が必要です。

### DRM保護コンテンツ
**DRM保護アプリ**（Netflix、Disney+、Amazon Prime Video、Кинопоиск、および同様のストリーミング
サービスなど）は、Androidのセキュリティ制限により、画面キャプチャモードでは**動作しません**。
これはAndroid MediaProjection APIの根本的な制限で、回避できません。

**なぜこうなるか:**
- Androidは海賊版防止のため、DRM保護コンテンツの画面キャプチャをブロックします。
- これはシステムレベルで強制され、アプリケーションでは上書きできません。

**解決策:**
1. **カメラモードを使う**: 設定でキャプチャソースを**Camera**に切り替えます。この方式は画面
   キャプチャではなくデバイスカメラを使うため、DRM保護コンテンツでも動作します。カメラを
   テレビ画面に向けたスマートフォン/タブレットの配置が必要です。
2. **アンビエントライトを無効化**: DRM保護コンテンツ視聴中はアンビエントライト機能をオフにします。
3. **非DRMソースを使う**: DRM保護のないソース（ローカルファイル、YouTubeなど）から視聴します。

**注意:** カメラモードでは、正確な色キャプチャのためにコーナー位置の適切な校正が必要です。
